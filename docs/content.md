# Content

Where every piece of copy lives, how it reaches the page, and the conventions pages follow.

## The rule

All copy, rates, venues, videos, apps, resume entries and profile links live in typed modules under `src/lib/content/`. Pages, the `Seo` component, the JSON-LD and `llms.txt` all render from those modules, so the visible page and its metadata stay in step. Edit the module, never the page markup.

Each module has a `.test.ts` beside it pinning the values that must not drift (rates, links, order). When you change a value on purpose, update its test in the same change. `privacy.test.ts` checks every module for email addresses other than `andrew@andrewsunada.com` and for the accounts the site must never name.

## Module map

| Module | Holds | Rendered on |
|---|---|---|
| `site.ts` | Identity, email address, profile links, footer links, YouTube, GitHub and eBay URLs, lesson booking, email-link helper, contact page copy, navigation | Everywhere |
| `home.ts` | Home page section copy | `/` |
| `coaching.ts` | Coaching offers (summary, details, rates), venues, workshop titles, coaching page copy including the drill library | `/coaching/`, home offers, `Service` JSON-LD, `llms.txt` |
| `drills.ts` | The four drill library topics | `/coaching/#drills` |
| `wsdc.ts` | WSDC number and division, registry URLs, dance introduction | `/dance/` header, home dance section, `Person` JSON-LD, `llms.txt` |
| `videos.ts` | `mostWatchedVideos` (dance page) and `featuredVideos` (home page) | `/dance/`, `/`, `VideoObject` JSON-LD |
| `apps.ts` | App projects: pitch, stack, status, link | `/apps/`, home featured app, `SoftwareApplication` JSON-LD |
| `resume.ts` | Resume entries | `/resume/` |
| `photos.ts` | Registered photos with `alt` and caption | Wherever `sitePhotos.<key>` is used |
| `types.ts` | Shared types for all of the above | — |

Per-page titles and descriptions live in `src/lib/seo/pageMeta.ts`. JSON-LD builders are in `src/lib/seo/structuredData.ts`; `llms.txt`, `sitemap.xml` and `robots.txt` are generated by `src/lib/seo/siteFiles.ts`. A change to an offer summary, venue or video therefore also changes the structured data and `llms.txt`. Grep for the old text across `src/` before assuming a change is page-only.

## Email links

There is no contact form on the site. Every call to action that asks a visitor to get in touch opens their email app with a `mailto:` link built by `getEmailUrl({ subject, body? })` in `site.ts`, which URL-encodes both fields.

| Constant | Subject | Body | Used by |
|---|---|---|---|
| `lessonBookingEmailUrl` | Book a lesson | — | Every "Book a lesson" button |
| `drillLibraryEmailUrl` | Your drill library | Hey Andrew! I would love to learn more about your drill library. | "Ask about the drill library" button |

Add a new enquiry the same way: a named constant in `site.ts` built with `getEmailUrl`, plus a test pinning the exact URL.

"Book a lesson" is the `BookingButton` component. When `privateLessonBookingUrl` in `site.ts` holds a Calendly link, the button opens Calendly; while it is empty, the button uses its `fallbackPath`, which is `lessonBookingEmailUrl`. `BookingButton` with `bookingUrl=""` is also the site's filled button style for any email call to action.

The other coaching enquiry links ("Ask about workshop dates" and similar) use `getContactPath(topic)` and land on `/contact/`, which shows the email address and profile links.

## Contact

`/contact/` shows the header with "Book a lesson", then "Or write to me directly" with the email address, then the profile links. The `ContactForm` component (Formspree with Cloudflare Turnstile) and its `PUBLIC_CONTACT_FORM_ENDPOINT` and `PUBLIC_TURNSTILE_SITE_KEY` variables remain in the codebase, but no page renders the form.

## Footer links

The footer renders `footerLinks` from `site.ts`: the five profiles in `socialLinks`, then **eBay** (`ebayStoreUrl`) and **Email** (`mailto:` the contact address). `/contact/` renders `socialLinks` alone, since it already shows the email address. Add a link to `footerLinks` when it belongs in the footer only, and to `socialLinks` when it is a profile that also belongs on `/contact/`.

## External links

Every link to another site opens in a new tab with `target="_blank" rel="noopener noreferrer"`, so the visitor keeps andrewsunada.com open.

- `ArrowLink` and `Card` detect `http://` and `https://` hrefs and add both attributes themselves. Pass them any URL.
- `SocialLinks` adds them with `rel="me noopener noreferrer"`, which also tells profile sites the links are Andrew's. It leaves `mailto:` links without either attribute.
- Any plain `<a>` to an outside URL in a page or component must carry both attributes. The scan in [local-development.md](local-development.md#quick-checks-without-a-browser) finds any that don't.

Internal links and `mailto:` links open in the same tab.

## Apps

Each entry in `apps.ts` has a `status` shown as the card's eyebrow, and an optional `linkUrl` with `linkLabel`. A non-empty `linkUrl` links the card title, shows the label with an arrow, and adds `url` to the app's `SoftwareApplication` JSON-LD.

| App | Status | Link |
|---|---|---|
| Meeko | Live | https://www.meekoapp.com |
| TK Wallet | Live | https://tkwallet.me/home |
| WeMove | Paused | none |
| Bingo | Open source | https://github.com/tksaeku/bingo |

To find an app's live address, read the deploy notes in that app's own repo (`~/Projects/<app>/.claude/specs/deploy.md` or its `CLAUDE.md`), then confirm it answers with `curl -s -o /dev/null -w '%{http_code}' <url>`. Domain-looking strings in env files are not reliable: `https://tkwallet.com` is TK Wallet's Auth0 API audience identifier, not a website, and does not resolve.

Never link `samuraijs`, `SwingCoder911`, parked domains or private repos.

## Coaching page

- **Workshops**: the offer `summary`, two `details` bullets, then a two-column block with "Where I teach" (venue name linked, city below) and "With workshops like…" (titles only) on the left and the workshop photo on the right. Venues have no schedule field; workshops have only `slug` and `title`.
- **Drill library**: the introduction from `coachingPageCopy.drillLibrary`, the topics from `drills.ts` in a two-column list, and the email button labelled by `drillLibrary.emailLabel`.

## Dance page

The header shows `WSDC #8715 · All-Stars` and the bio. Below it are two sections: **01 Videos** (`mostWatchedVideos` in a grid, no year headings) and **02 Channel** (a link to the YouTube channel). How the videos are chosen is in [youtube-videos.md](youtube-videos.md).

## Photos

Originals live in `assets/photos/` (git-ignored). To use one, copy it into `src/lib/images/` and register it in `photos.ts` with `alt` text and a caption; `photos.test.ts` pins the set of keys. When a page stops using a photo, remove its entry, its import and the file in `src/lib/images/`. [photos.md](photos.md) catalogues the library and where each shot could be used.
